# Rainyun OSS Sync

Rainyun object storage is S3-compatible. The project image includes a token-protected S3-to-WebDAV gateway so the existing WebDAV Sync screen can upload canvases, assets, generation history, and local media files to Rainyun OSS.

Keep the Access Key and Secret Key in container environment variables only. Never put them in frontend code, a Dockerfile, Git, or a public screenshot.

## Container environment variables

```env
S3_ENDPOINT=https://your-rainyun-api-endpoint
S3_REGION=rainyun
S3_BUCKET=your-bucket
S3_ACCESS_KEY=your-access-key
S3_SECRET_KEY=your-secret-key
STORAGE_API_TOKEN=a-separate-private-sync-token
```

Use the API endpoint shown by Rainyun without appending the bucket name. `STORAGE_API_TOKEN` is not a Rainyun credential; it protects the deployed sync endpoint and should be an independent random value.

The container still listens on port `3000`. After deployment, `/healthz` should report `storageConfigured: true`.

## Frontend configuration

Open Settings → WebDAV Sync and enter:

- WebDAV URL: `https://your-site.example/api/webdav`
- Username: any non-empty name, such as `canvas`
- Password: exactly the server's `STORAGE_API_TOKEN`
- Remote directory: `infinite-canvas`

Test the connection before running Sync. The first sync writes manifests and media objects under the `infinite-canvas/` prefix.

## Security and data notes

- Use the site over HTTPS because the sync token is carried with Basic Auth.
- Never paste the Rainyun Access Key or Secret Key into the browser's WebDAV fields.
- Canvas data is still written to browser IndexedDB first. OSS is the manual sync and cross-device merge target, not a real-time collaboration database.
- If Rainyun labels the object-storage generation as a test service, do not use it as the only copy of important assets.
